## 1. 设计基调：实用、克制、效率优先

本系统的设计判断只有一个出发点：**这是给吊装调度、现场司机与财务人员每天使用的生产工具，不是展示页**。界面存在的目的是让「看状态、做操作」更快更准，任何不服务于这两个目标的装饰都是噪音。

三个原则贯穿全部端：

**原则一：信息为先，层级克制。** 一屏只承担一个主任务。工单状态、冲突提醒这类关键信息放在用户目光的第一落点，次要信息靠后或折叠。页面内最多两级视觉层次：关键信息（大字号 / 语义色 / 加粗）与辅助信息（次级色 / 小字号），不做第三层装饰性强调。

**原则二：操作直达，减少跳转。** 高频操作（签到、签退、异常上报、冲突处置、派单）在一屏内完成，关键路径控制在 2 次点击内。参考开元业务软件平台「效率优先」的设计哲学：顶部固定导航、功能入口扁平排列、减少干扰元素，让用户聚焦当前任务而不是在界面中寻找入口 [Expert judgment，参考开源业务软件平台效率优先经验]。

**原则三：色彩语义化，克制用色。** 全系统只使用一套语义色，同一种状态在任何端都是同一种颜色（进行中=蓝、异常=红、已完成=绿、冲突=琥珀）。色彩只用于表达状态与引导注意，不用于装饰。大面积背景一律使用中性色（深蓝灰 / 浅灰），彩色只出现在语义点位上。

风格反面清单（禁止出现）：

- 渐变背景、彩色卡片堆叠、圆角过大的「糖果感」组件
- 每屏超过 3 个强调色的「彩旗效应」
- 无意义的入场动画、弹跳、闪烁（呼吸高亮仅限报警置顶区）
- 装饰性插画、Emoji、外部字体与 CDN 依赖

## 2. 色彩系统

### 2.1 品牌与中性色

品牌主色采用深蓝灰，参考开元平台「深蓝 + 浅灰」的效率型配色：深蓝传递专业与可靠，浅灰保证信息密度下不刺眼 [Expert judgment]。深蓝灰同时与户外强光场景的对比度要求兼容（见 §5.1）。

| 令牌 | 浅色端（后台 / 小程序 / H5） | 深色端（大屏覆写） | 用途 |
|---|---|---|---|
| `--brand` | `#1d4ed8`（深蓝） | `#38bdf8`（亮蓝） | 主操作、当前选中、进行中 |
| `--brand-weak` | `#dbeafe` | `rgba(56,189,248,.15)` | 选中背景、弱强调底 |
| `--bg` | `#f5f7fa`（浅灰） | `#060c1a` | 页面底 |
| `--panel` | `#ffffff` | `rgba(13,28,54,.72)` | 卡片 / 面板底 |
| `--line` | `#e5e7eb` | `rgba(64,156,255,.18)` | 边框与分隔线 |
| `--txt` | `#1f2937` | `#dbe7f5` | 主文本 |
| `--sub` | `#6b7280` | `#7d93b5` | 次级文本、说明 |

### 2.2 语义色（全端唯一）

| 语义 | 取值 | 用途 | 追溯 |
|---|---|---|---|
| 进行中 / 已开工 | 蓝 `--brand` | 工单进行中、车辆作业中 | PRD 10.1 色彩语义化 |
| 异常 / 高等级报警 / 停用 | 红 `#dc2626` | 异常上报、报警置顶、车辆停用 | PRD 10.1 |
| 已完成 / 空闲 | 绿 `#16a34a` | 工单完成、车辆空闲 | PRD 10.1 |
| 冲突提醒 / 中等级报警 | 琥珀 `#d97706` | 互斥冲突卡片、超时预警 | PRD 4.18、9.6 |
| 第三方派单 / AI 标识 | 紫 `#7c3aed` | 第三方派单车辆、AI 相关 | 原型既有约定 |
| 已到场 / 维保 | 黄 `#eab308` | 到场未开工、维保中 | 原型既有约定 |

语义色的使用边界：**同一时间同一屏内，彩色元素不超过 5 个**（一个页面通常只有 1 个主状态色 + 1 个告警色）。状态以「图标 + 颜色 + 文字」三重表达，色盲用户通过图标与文字仍可辨识 [Data-backed：PRD 10.3]。

## 3. 字体与字号

### 3.1 字体

不引入外部字体（离线可用约束，见 01 §4.2），使用系统字体栈：

- 数字与中文混排：`PingFang SC`、`Microsoft YaHei`（回退 `system-ui`、`sans-serif`）
- 数字（工单号、车牌、工时、金额）：等宽数字特性，`font-variant-numeric: tabular-nums`，保证表格列对齐
- 大屏数值：`DIN` / `Roboto Mono` 不可用时回退系统字体，数字以 tabular-nums 对齐 [Expert judgment]

### 3.2 字号阶梯

| 令牌 | 大小 | 用途 |
|---|---|---|
| `--fs-hero` | 20px（移动端）/ 24px（后台） | 首页核心信息、大屏 KPI 数值 |
| `--fs-title` | 17px | 页面标题、卡片标题 |
| `--fs-body` | 15px | 正文、列表项 |
| `--fs-caption` | 13px | 次级说明、时间戳、表头 |
| `--fs-mini` | 12px | 标签、角标、表格内小字 |

户外强光场景（司机端）正文下限为 15px，核心操作按钮文字不低于 17px [Data-backed：PRD 10.1 高对比大字号]。

## 4. 间距、圆角与阴影

| 令牌 | 取值 | 用途 |
|---|---|---|
| `--space-xs` | 4px | 图标与文字间隙 |
| `--space-sm` | 8px | 卡片内紧凑分组 |
| `--space-md` | 12px | 列表项间距 |
| `--space-lg` | 16px | 卡片内边距、页边距 |
| `--space-xl` | 24px | 区块间距 |
| `--radius` | 8px | 卡片 / 按钮统一圆角（大屏 6px） |
| `--radius-lg` | 12px | 弹窗、大卡片（移动端） |
| 阴影 | 仅浅色端使用 `0 1px 2px rgba(15,23,42,.06)` | 卡片浮起，深色端不依赖阴影改用边框 |

圆角纪律：**统一 8px，不堆叠大圆角**。按钮、输入框、卡片共用同一圆角，避免「按钮圆角 > 卡片圆角」的反直觉组合。

## 5. 三端适配规则

### 5.1 移动端（小程序 + H5，`apps/mobile`）

户外强光是司机端的第一约束 [Data-backed：PRD 10.1]：

- 对比度：主文本与背景对比度 ≥ 7:1；语义色与背景对比度 ≥ 4.5:1（红绿蓝均在浅灰底上验证）
- 大热区：核心操作按钮高度 ≥ 44px，全宽优先；戴手套可点按
- 单手可达：主操作放拇指区（屏幕下半部），Tab 栏承载次级入口
- 首页即当前工单：首页首屏只呈现「当前工单 + 核心动作」，冲突提醒卡片置顶于工单卡上方（见 05 §5.3）
- 弱网：加载态、失败重试、离线提示三态齐全，禁止白屏

移动端组件一律自研（01 §4.3），组件清单与令牌映射：卡片（`--panel` + `--line` + `--radius`）、主按钮（`--brand` 底 + 白字 + 图标）、状态标签（语义色文字 + `--brand-weak` 系浅底）。

### 5.2 后台管理（`apps/admin`）

后台是信息密度最高的端，参考开元平台「信息层级分明、导航固定、减少干扰」[Expert judgment]：

- 布局：顶栏固定（系统名 + 全局搜索 + 报警铃铛），侧边可折叠菜单，内容区面包屑 + 筛选区 + 工具栏 + 表格 + 分页（见 07 §2.3）
- 表格：每行高 48px，表头 `--fs-caption` 次级色，行 hover 浅灰底；数字列右对齐 + tabular-nums
- 筛选区：一行内承载，条件可重置；工具栏（导出 / 批量）与筛选区分离
- 弹窗：仅用于二次确认与强依赖表单；信息查看用抽屉 / 详情页，不弹大窗
- 采用 Element Plus 默认组件 + 本手册令牌覆写：覆盖 `--el-color-primary` 为 `--brand`，圆角 `--el-border-radius-base` 为 8px，去除阴影默认值改用边框

### 5.3 数据大屏（`apps/screen`）

大屏独立深色主题，仅覆写令牌不另建色板（01 §4.3）：

- 深色令牌见 §2.1 右列与 06 §6.1，语义色在深底上取亮色值（蓝 `#38bdf8`、红 `#fb4d63`、绿 `#3ddc97`）
- 观看距离：KPI 数值 ≥ 28px，图表图例 ≥ 14px；对比度按投影环境验证
- 动效克制：仅「报警置顶呼吸高亮」与「数据刷新过渡（500ms 淡入）」两处，其余静态
- 布局密度：16:9 固定，分区见 06 §5.1

## 6. 图标系统

- 统一 24×24 网格、线宽 2、圆角端点的描边内联 SVG sprite，`currentColor` 继承颜色 [Data-backed：01 §4.2、PRD 10.3]
- 禁止外部 CDN、图标字体、位图与 Emoji；图标清单以 05 §9.1 为准，全端共用同一 sprite
- 图标语义唯一：同一功能全端同一图标；状态图标与语义色一一绑定

## 7. 动效与反馈原则

| 场景 | 动效 | 时长 |
|---|---|---|
| 页面进入 | 首屏关键内容淡入（不做全页滚动动画） | 300ms |
| 报警置顶 | 呼吸高亮（仅大屏与后台报警中心） | 1.5s 周期 |
| 操作反馈 | 按钮按压态 / 成功 / 失败 / 加载态即时可见 | 即时 |
| 数据刷新 | 数值 / 图表淡入过渡 | 500ms |
| 列表增删 | 无动画（克制）或 200ms 淡入 | ≤ 200ms |

动效纪律：**一个页面同时最多一个持续动画**；除报警呼吸高亮外，不设循环动画。所有反馈必须有「成功 / 失败 / 加载中」三态，不得静默失败 [Data-backed：PRD 10.4]。
