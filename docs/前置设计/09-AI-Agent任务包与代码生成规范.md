## 1. 使用方式

本文件不是一份巨型提示词，而是一套任务包与规范。使用时按文档 00 §4.2 的任务依赖图，逐任务取用：找到当前可执行的任务，复制其提示词骨架，按「输入文档 → 任务范围 → 交付物 → 验收标准」的顺序投喂给生成 Agent，一个任务一次会话，完成后按 §6 验收再进入下一个任务。

三条使用纪律：

- 一次会话只做一个任务，禁止把多个任务合并投喂
- 契约只读不写。生成 Agent 不得修改 01 §6.3 枚举、03 的接口路径与错误码；发现契约缺口时先改文档、再改代码
- 每个任务的产出必须落在 §2.3 规定的目录范围内，不得越界生成其它模块代码

## 2. 代码生成总规范

### 2.1 技术栈约定

| 层 | 约定 |
|---|---|
| 后端 | Java 17 + Spring Boot 3.x（版本待确认）+ MyBatis-Plus，构建工具 Maven |
| 数据库 | MySQL 8，字符集 utf8mb4，表名与字段遵循文档 01 §6.2 |
| 中间态存储 | 不引入缓存中间件；登录态失效、验证码、幂等键落 MySQL（见文档 10 §4） |
| 后台前端 | Vue 3 + Vite + Element Plus + Pinia + Vue Router |
| 移动端 | uni-app（Vue 3 语法），一套源码编译 H5 与微信小程序 |
| 大屏 | Vue 3 + ECharts |
| 部署 | Docker + Docker Compose，容器统一 crane- 前缀 |

### 2.2 后端结构约定

```
backend/
└─ src/main/java/com/crane/
   ├─ common/          # 统一响应、异常、错误码、分页、鉴权注解、工具
   ├─ config/          # 配置类（鉴权、跨域、定时任务）
   └─ modules/
      ├─ auth/ iam/ staff/ demand/ workorder/ dispatch/
      ├─ attendance/ exception/ change/ conflict/ notify/
      └─ stat/ ai/ file/ system/
         └─ 每个域内固定分层：controller / service / mapper / entity / dto / enums
```

- Controller 只做参数校验与编排，业务规则写在 Service
- 统一响应体 `{ code, message, data, traceId }`，由切面或统一封装产生，Controller 不自行拼装
- 异常统一由全局异常处理器转换为错误码，禁止在 Controller 里 try-catch 后返回裸字符串
- 枚举与文档 01 §6.3 一一对应，一个枚举一个类

### 2.3 前端结构约定

```
frontend/
├─ apps/admin/     # 后台管理（Vue 3 + Element Plus）
├─ apps/screen/    # 数据大屏（Vue 3 + ECharts）
├─ apps/mobile/    # H5 + 微信小程序（uni-app）
└─ packages/shared/# 类型、枚举、接口客户端、权限位、SVG 图标、主题令牌
```

- 接口调用统一走共享层的接口客户端，禁止在页面里直接使用请求库
- 枚举、类型从共享层导入，禁止在页面内各自定义状态字面量
- 图标使用共享层的内联 SVG sprite，禁止引入外部图标库、CDN、字体或图片；禁止使用 Emoji
- 权限控制使用共享层的权限位，路由与按钮级共用同一套权限码

### 2.4 命名与提交规范

| 项 | 规范 |
|---|---|
| 分支 | 主干 `main` 只接受已验证代码；开发分支 `feat/<task-id>-<简述>`；修复 `fix/<task-id>-<简述>` |
| 提交 | `type(scope): subject`，type ∈ feat / fix / refactor / docs / chore / test |
| 提交粒度 | 一个任务一个或多个相关提交，禁止跨任务混杂提交 |
| 后端命名 | 类 PascalCase，方法 camelCase，表与字段 snake_case，与文档 01 §6.2 一致 |
| 前端命名 | 组件 PascalCase，文件与目录 kebab-case，Pinia store 以 use 前缀 |

## 3. 通用提示词骨架

每个任务的提示词按以下骨架填写。骨架固定，内容按任务替换。

```
角色：你是 <后端 / 前端 / DevOps> 工程师，负责 <系统名> 的 <任务范围>。

输入文档（生成前必须先阅读，不得凭记忆臆造）：
- 01 总体技术架构设计（HLD）§<相关章节>
- 02 数据库设计文档 §<相关表>
- 03 接口设计规范 §<相关接口编号>
- 0X <对应模块设计文档> §<相关章节>
- 11 前端设计手册 §<前端任务引用色彩 / 组件 / 动效令牌，后端任务无需引用>

任务范围：<一句话描述本任务要交付的功能单元，明确不含什么>

交付物：<文件 / 目录清单>

验收标准：
1. <可执行、可观测的验收项>
2. <可执行、可观测的验收项>

禁止事项：
- 不得修改 01 §6.3 枚举与 03 的接口路径、错误码
- 不得越界生成任务范围外的模块
- 不得使用 Emoji、外部 CDN、字体或图片，不得出现任何 AI 厂商或品牌名
- 不得臆造版本号、容量数字，未确认处保留 [待确认] 并写入代码注释
```

## 6. 验收与回归规则

每个任务完成后按以下顺序验收，未通过不得进入下游任务。

| 步骤 | 内容 |
|---|---|
| 自检 | 生成 Agent 按提示词逐条对照验收标准，列出已通过与未通过项 |
| 契约核对 | 检查枚举、路径、错误码与 01 §6.3、03 完全一致，无自造字面量 |
| 运行验证 | 后端任务须启动服务并调用相关接口；前端任务须启动应用并走通对应页面 |
| 回归检查 | 确认本任务未破坏已通过的上游任务功能 |
| 提交 | 按 §2.4 规范提交，一个任务一个或多个相关提交 |

联调阶段（T-50）以用例为准，用例覆盖：需求单到工单的完整闭环、派单前置校验与并行限制、接单拒单与重派、签到签退与自动结单、变更审批、冲突提醒四类触发与升级、权限隔离、双通道通知、H5 与小程序一致性。

## 7. 禁止事项清单

- 禁止将整体系统、整体后端、整体前端作为一个提示词投喂
- 禁止在生成代码中修改 01 §6.3 枚举字面量、03 的接口路径与错误码
- 禁止越界生成任务范围外模块；禁止顺手重构未在任务范围内的代码
- 禁止使用 Emoji、外部 CDN、外部字体、外部图片；图标只用共享层内联 SVG sprite
- 禁止在文档、界面与代码注释中出现任何 AI 厂商或品牌名，一律使用通用词「AI」
- 禁止臆造版本号、库版本、容量数字与第三方密钥；未确认处保留 [待确认]
- 禁止跳过验收直接提交主干；禁止在主干分支直接开发
